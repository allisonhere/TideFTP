why bother

A dedicated, polished, two-pane transfer client for the terminal is a niche almost nobody occupies. Most "TUI FTP" is a general file manager with a protocol layer bolted on, or a scriptable CLI with no interface at all. TideFTP is the part in between — the queue, the progress, the conflict prompts, on screen.

what's in it

The whole client, keyboard-first

Three things a transfer client is for. TideFTP takes each one seriously.

Move

A real transfer queue

Parallel transfers, per-file and overall throughput, a live ETA, retry and cancel per row. The thing mc and ranger never had.

Conflict policieson collision

Overwrite if newer, if a different size, resume, rename, skip. Apply to one, apply to all, or remember it for the session.

Directory mirrorM

Walks both trees, queues only what's missing or changed, shows a new / updated / unchanged plan first. Prune is one keystroke, and opt-in.

Resume, not restart

An interrupted transfer picks up from the byte it stopped at, on both ends.

Inspect

Preview without downloadingv

The first 128 KB as syntax-highlighted text, or a hexdump for binaries. It never pulls the whole file.

Edit in placee

Checks a file out to a temp copy, opens $EDITOR, writes it back if you changed it. Either pane.

Filter & sort/   s

Type to narrow a listing by glob or substring; cycle sort by name, size, date or type. Per pane.

Change permissionsm

An octal prompt pre-filled with the current mode, echoing back the rw-r--r-- it decodes to. Local and SFTP.

Keep it safe

Post-transfer verify

Opt in, and every completed transfer is re-read on both ends and compared by SHA-256. A mismatch is a failure you can retry.

Strict host keys

Checked against known_hosts by default, with an explicit trust-once / trust-and-remember prompt for a new one. No silent accept.

Passwords never in argv

Read from the environment or typed into the form — a flag would leave the secret in the process table for every other user on the box.

Auto-reconnect

Redials after an unrequested drop, backing off 2/4/8/15/30 s, and puts you back in the directory you were in.

quickstart

Two minutes

Go 1.26+. No install-time network beyond the module cache.

Build it

$ git clone https://github.com/allisonhere/TideFTP
$ cd TideFTP
$ go build -o tideftp ./cmd/tideftp

Connect

# open straight onto a server…
$ ./tideftp --host files.example.com --user deploy --path /var/www

# …or just launch and press c for the server list
$ ./tideftp

FTP and FTPS read the password from TIDEFTP_FTP_PASSWORD. SFTP uses your agent and ~/.ssh keys. FTPS verifies the server certificate; point --ftps-ca at a PEM for a self-signed one.

the honest part

What it isn't, yet

  • Not a cloud client. SFTP, FTP and FTPS only. S3, GCS and Dropbox are rclone's job.
  • Not scriptable. No headless mode. For cron and pipelines, lftp and rclone win outright.
  • Still filling edges. Queue persistence across restarts, bandwidth limiting and directory bookmarks are on the roadmap, not in the build.
  • Pre-1.0, one maintainer. lftp has absorbed decades of protocol quirks; TideFTP handles what pkg/sftp and jlaffaye/ftp expose — which is why FTP has no chmod.
