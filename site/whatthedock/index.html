the idea

If docker ps works on your machine, WhatTheDock has a decent shot at working too. It uses Docker's normal defaults and puts the everyday operations — logs, restarts, edits, host switches — one or two keystrokes away instead of a shell history search.

what it does

The everyday operations

Not a Docker course — the handful of things you actually reach for.

See it

What's running, at a glance

A fleet summary line, then every container with a status dot and a per-container CPU / memory / network sparkline row.

Colour-coded logsl   L

Filter to errors, warnings, info or all; jump to the end and follow live; page back through history; copy the visible filtered lines.

A problems panep

Restart loops and unhealthy containers surfaced together — and a asks a configured AI provider to analyse the selected one.

Stats graphsg

CPU, memory and network over time when a sparkline isn't enough.

Change it

Start, stop, recreates   Alt+r   u

Toggle a container, restart it, or u to pull the latest image and recreate it in place.

Create & edit with a live previewn   m

A form for standalone containers, Compose services, or whole stacks — with the generated YAML shown as you type, or edit the YAML directly.

CloneC

Duplicate a container or service as a starting point for the next one.

Shell ine

Drop straight into a running container.

Move it between hosts

Local and remote, one list

Manage several Docker hosts — local sockets and SSH — from the same screen, Compose reads and writes included.

Graceful host control

Shut down or reboot a host from inside the app, cleanly.

The Container Clipboard

Copy a running container's whole configuration off one host and recreate it on another — no hand-copied docker run flags.

  1. On the source host, select the container and press y to yank its config.
  2. Switch to the target host in the host list.
  3. Press P to paste — WhatTheDock recreates it there.

The Compose catalog

A library you keep

Hold onto Compose files, edit them safely, add notes, and later make one live on any local or remote host.

Practical, not magical

A single-service file edits as a service; a multi-service file is a stack; editing a stack row edits the whole file. It tells you which it's doing.

install

Get it

The installer checks the binary runs, then drops it in /usr/local/bin (or ~/.local/bin if that's not writable).

One line

$ curl -fsSL https://raw.githubusercontent.com/allisonhere/whatthedock/main/scripts/install.sh | sh

From source

$ go install github.com/allisonhere/whatthedock/cmd/whatthedock@latest

Kick the tyres without Docker

$ whatthedock --demo
the honest part

Where it's at

  • Early, but the main workflow is usable. See, log, start/stop/edit/clone/recreate, multi-host and Compose all work today.
  • It follows Docker's defaults. No custom socket dance — if docker ps works, this should.
  • Compose support is scoped. Service and stack edits, catalog, and docker compose runs on local and SSH hosts — not every exotic Compose feature.
  • AI analysis is opt-in and only runs on the problem you press a on, after you configure a provider.
